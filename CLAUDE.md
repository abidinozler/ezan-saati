# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Android app (Kotlin + Jetpack Compose): offline prayer times, countdown, qibla compass, per-prayer notifications, home-screen widget, lock-screen countdown notification. Code comments are in Turkish — keep it that way. Don't add network/API calls; prayer times must stay fully offline. Distributed as APK via GitHub Releases (`release.sh`, repo `abidinozler/ezan-saati`, phone updates with Obtainium); a Play Store release is planned (needs a non-debug upload key and replacing `USE_EXACT_ALARM` with user-granted `SCHEDULE_EXACT_ALARM`).

Localization: all user-visible text lives in `res/values*/strings.xml` — `values/` is English (fallback), plus `values-tr`, `values-ar` (RTL), `values-de`. Add every new string to all four. Enums carry `@StringRes` (`Prayer.nameRes/remainingRes`, `CalculationMethod.nameRes`, `MoonPhase.nameRes`); times are always formatted with `Texts.TIME` (24h, Latin digits). Calculation method is user-selectable (`CalculationMethod`, default auto via `suggestFor(lat, lng)`; only Diyanet has temkin offsets) plus Shafi'i/Hanafi asr.

## Build & test

Android Studio's bundled JBR is Java 25, which requires Gradle 9.x (project: Gradle 9.8.2, AGP 9.5 with built-in Kotlin — there is no separate `kotlin-android` plugin). Run from the Bash tool:

```bash
JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew assembleGithubDebug testGithubDebugUnitTest
# Play bundle (AAB) + Play lint
JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew bundlePlayRelease lintPlayRelease
# single test
JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew testGithubDebugUnitTest --tests "com.ezansaati.app.CalculatorTest.istanbulYazGundonumu"
```

Build output is **not** in `app/build`: `settings.gradle.kts` redirects every project's build dir to `%LOCALAPPDATA%\EzanSaatiBuild\<project>` because OneDrive locks files and breaks builds. Outputs: `...\outputs\apk\github\{debug,release}\app-github-*.apk` and `...\outputs\bundle\playRelease\app-play-release.aab`; after changes, copy the APK to the project root as `EzanSaati.apk` — the owner installs it on their phone manually (don't adb-install to networked devices).

Flavors (dimension `dagitim`): `github` (sideload/GitHub Releases; `USE_EXACT_ALARM`, direct battery-optimization exemption request) and `play` (`src/play/AndroidManifest.xml` removes those and uses user-granted `SCHEDULE_EXACT_ALARM`; code branches on `BuildConfig.PLAY_STORE`). `play` is signed with the upload key `keystore/upload.jks` (credentials in `keystore/upload.properties`, SHA-256 `9D:4B:22:1A…`). Store listing text lives in `fastlane/metadata/android/<locale>/`, graphics are generated by `fastlane/make_graphics.py`; privacy policy is `PRIVACY.md`.

Signing: all other variants use `keystore/ezan.keystore` (a copy of the debug key that signed the first installed APK, SHA-256 `A7:72:AB:BD…`; gitignored, backed up only by OneDrive). Never replace it — a different key means the owner must uninstall and lose settings. `versionCode` is minutes since 2026-01-01 (auto-increments per build), `versionName` = `1.1.<versionCode>`.

Only JVM unit tests exist (`app/src/test/.../CalculatorTest.kt`, `LunarTest.kt`), covering `PrayerCalculator` (methods, asr), `nextPrayer`, `QiblaCalculator` and moon phase / Hijri date.

## Architecture

No DI, no database. `SettingsRepository` (SharedPreferences `ezan_settings`) is the single source of truth and is read synchronously from the ViewModel, BroadcastReceivers and the widget alike. Prayer times are never stored — `SettingsRepository.timesFor(date)` recomputes them from the saved location + user minute offsets via `PrayerCalculator` every time.

`PrayerCalculator` = PrayTimes.org algorithm with Diyanet params (fajr 18°, isha 17°, Shafi asr) plus `DIYANET_TEMKIN` fixed offsets, then per-prayer user offsets (±15 min, from Settings screen).

**Alarm chain** (`notification/`): `AlarmScheduler.scheduleNext` sets exactly one exact alarm (fixed request code) for the next notification-enabled prayer within today/tomorrow. `PrayerAlarmReceiver` shows the notification (skipped if >15 min late) and schedules the next one. `SystemEventReceiver` re-arms the chain and widget on boot, time/timezone change, package update and exact-alarm permission change. `MainViewModel.refresh()` also re-arms both — any settings change goes through `refresh()`.

**Widget + lock-screen countdown** (`widget/PrayerWidget.kt`, `notification/CountdownNotification.kt`): `PrayerWidget.updateAll` refreshes both. RemoteViews and the ongoing notification use a `Chronometer` counting down on their own; they are only redrawn by a non-wakeup `RTC` alarm at the next prayer time or midnight (whichever is first), via `ACTION_REFRESH`.

UI: single `MainActivity` hosting Compose screens (`ui/home`, `ui/qibla`, `ui/settings`) backed by one `MainViewModel` exposing `StateFlow<UiState>`. Location comes from GPS (`FusedLocationProvider`, coarse) snapped to the nearest of the 81 provinces in `data/Cities.kt` for naming, or picked from that list directly.
